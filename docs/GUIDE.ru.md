## Установка, подключения и обновление

### Готовый архив

Нужны Windows 10/11 (64-бит) и настольный Excel и/или Word. Установка — **для текущего пользователя без администратора**.
Python и зависимости находятся в архиве; установка не обращается к PyPI и ничего не загружает из сети.
Распакуйте архив целиком в короткий каталог и запустите `install.cmd`. Мастер предлагает клиентов и доступ.
Enter сохраняет настройки существующих записей; для новых записей по умолчанию полный доступ.

По умолчанию программа находится в `%LOCALAPPDATA%\Programs\office-live-mcp\app`. В
`%LOCALAPPDATA%\office-live-mcp\state.json` хранятся корень установки, версия и регистрации: клиент, область,
полный путь конфигурации, имя `office-live`, команда, отпечаток записи и время. Резервная копия состояния — `state.json.bak`.
Запись `pending` означает прерывание или неудачное контрольное чтение; исправьте указанный файл и повторите `setup`.
Журналы документов, состояние, копии конфигураций и отчёт удаления автоматически не стираются.

Примеры ниже — команды **cmd.exe**, `D:\Office Live` — выбранный каталог:

```bat
:: Только программа, без подключения клиентов
install.cmd --target "D:\Office Live" --yes --clients none

:: Одна установленная копия, два клиента
"D:\Office Live\app\office-live-mcp.exe" setup --yes --clients codex,zcode

:: Разные настройки двумя вызовами; второй не меняет Codex
"D:\Office Live\app\office-live-mcp.exe" setup --yes --clients codex --full
"D:\Office Live\app\office-live-mcp.exe" setup --yes --clients zcode --readonly

:: Позднее подключение ещё одного клиента без переустановки
"D:\Office Live\app\office-live-mcp.exe" setup --yes --clients cursor

:: Проектная регистрация
"D:\Office Live\app\office-live-mcp.exe" setup --yes --clients claude-code --scope project --project "D:\Проекты\Смета"

:: Нестандартный файл — ровно один клиент
"D:\Office Live\app\office-live-mcp.exe" setup --yes --clients zcode --config "D:\Конфиги\zcode.json" --readonly

:: Проверить план без создания файлов, замков и резервных копий
install.cmd --dry-run --yes --clients none
"D:\Office Live\app\office-live-mcp.exe" setup --dry-run --clients codex --readonly
"D:\Office Live\app\office-live-mcp.exe" uninstall --dry-run
```

`--config` записывает файл выбранного формата, но не настраивает его загрузку самим клиентом: укажите этот файл клиенту
его собственным способом. Нельзя сочетать `--config` с `--scope project`/`--project`.
Новые флаги `--config`, `--scope`, `--project`, `--force`, `--dry-run` доступны в `setup`; у `config` сохранён псевдоним `--path`.

### Клиенты и области

| Клиент | Пользовательская конфигурация | Проектная конфигурация |
|---|---|---|
| Codex | `%CODEX_HOME%\config.toml`, иначе `%USERPROFILE%\.codex\config.toml` | `.codex\config.toml`, только доверенные проекты |
| ZCode | `%USERPROFILE%\.zcode\cli\config.json`, `mcp.servers` | `.zcode\config.json`, `mcp.servers` |
| Claude Code | `%USERPROFILE%\.claude.json`, `mcpServers` | `.mcp.json`, `mcpServers` |
| Claude Desktop | `%APPDATA%\Claude\claude_desktop_config.json` | не поддерживается; понятный отказ |
| Cursor | `%USERPROFILE%\.cursor\mcp.json` | `.cursor\mcp.json` |
| VS Code | автоматический выбор пользовательского профиля не поддерживается; используйте `--config` | `.vscode\mcp.json`, `servers`, `type: stdio` |

Нестандартная область `custom` поддерживается для всех перечисленных форматов. Для совместимости `setup --clients vscode`
без области использует текущий проект; предпочтителен явный `--scope project --project DIR`.
Старое `config claude-code --scope local` сохранено (частная запись проекта внутри `.claude.json`, в state учитывается как
`project` вместе с точными ключами). `setup` предоставляет только `user` и `project`.
JSON с комментариями/завершающими запятыми (JSONC) не переписывается: преобразуйте в обычный JSON вручную.

Пути и форматы сверены с официальной документацией:
[Codex MCP](https://developers.openai.com/codex/mcp/),
[CODEX_HOME](https://learn.chatgpt.com/docs/config-file/environment-variables),
[ZCode](https://www.zcode.network/en/docs/mcp-services/),
[Claude Code](https://code.claude.com/docs/en/mcp),
[Cursor](https://prod.cursor.com/help/customization/mcp),
[VS Code](https://code.visualstudio.com/docs/agent-customization/mcp-servers).
Доверие проекту и разрешения на запуск серверов остаются настройками самого клиента; установщик их не меняет.

### Сохранение настроек и конфликты

Повторный `setup` сохраняет `OFFICE_LIVE_*`, другие переменные окружения и дополнительные параметры MCP (таймауты,
списки инструментов, включённость и т. п.). Явные `--readonly`, `--full`, `--toolsets`, `--allowed-dirs` и повторяемый
`--env OFFICE_LIVE_NAME=value` меняют только указанные настройки. `--reset` сбрасывает параметры своей записи.
`--full` снимает сохранённый `OFFICE_LIVE_MODE=readonly`; остальные параметры сохраняются.

Если `office-live` запускает другую программу/установку, будет отказ с путём и командой. Только явный `--force` разрешает
замену; для записи HTTP при такой замене убирается URL и выбирается stdio. Имя записи само по себе не доказывает владение.
Для исходников сравниваются Python **и аргументы запуска**, чтобы не затронуть другой сервер на том же Python.

Запись защищена файлом `.lock` рядом с конфигурацией (Windows `msvcrt`), перечитыванием и проверкой перед атомарным
`os.replace`. При замеченном параллельном изменении подготовка повторяется один раз либо команда отказывает.
Клиентские редакторы могут не соблюдать наш замок; при одновременном редактировании закройте настройки клиента и повторите
команду. Абсолютную транзакцию с редактором, игнорирующим блокировку, обычный файл не обеспечивает.
Перед изменением остаётся датированная `.bak-…`; повреждённый JSON/TOML сохраняется даже с `--force --reset`.
Для TOML на Python 3.10 нужен `tomli` (входит в зависимости). Необычная inline/dotted запись, которую нельзя безопасно
заменить с сохранением остального файла, требует ручной правки. Сбой одного клиента не мешает учесть успешные подключения других.

### Обновление и откат

Распакуйте **новый** архив и запустите его `install.cmd`. Без `--target` используется корень из state, если там есть действительная
метка `office-live-mcp.install`; иначе стандартный каталог. Нестандартная установка больше не дублируется молча.
Явный другой `--target` требует `--new-location`; это разрешение на отдельную копию, не автоматический перенос регистраций.

При обновлении существующие конфигурации не переписываются, новые обнаруженные клиенты не добавляются. Для добавления
нужен явный `--clients …` или последующий `setup`. Новая копия проверяется в промежуточной папке до переключения; прежняя
сохраняется до успешного запуска и проверки MCP в конечном пути. При провале проверки после переключения старая возвращается.
Если EXE занят, закройте использующих сервер клиентов и повторите. Приложения пользователя принудительно не завершаются.

Старая установка **без state**: при первом обновлении из нового архива укажите её прежний путь:

```bat
install.cmd --target "D:\Office Live" --yes
:: Следующее обновление уже запомнит этот путь
install.cmd --yes
```

Запуск `install` непосредственно из старого установленного EXE также позволяет определить корень по метке.
Старые пользовательские записи с точным путём этого EXE учитываются без изменения содержимого.
Неизвестные старые project/custom-конфигурации невозможно найти без реестра: повторите для них `setup --scope project …`
или `setup --config …`, чтобы поставить на учёт. Без манифеста нельзя достоверно отличить все старые библиотеки от чужих
файлов: они могут остаться в `app.old-*` или `app`; отчёт указывает место для ручной проверки.

### Отключение и удаление

```bat
:: Отключить только ZCode во всех учтённых областях; Codex и программа остаются
"D:\Office Live\app\office-live-mcp.exe" setup --yes --remove --clients zcode

:: Отключить одну проектную регистрацию
"D:\Office Live\app\office-live-mcp.exe" setup --yes --remove --clients cursor --scope project --project "D:\Проекты\Смета"

:: Все регистрации этой установки, файлы оставить
"D:\Office Live\app\office-live-mcp.exe" uninstall --keep-files

:: Отключить и удалить программу
"D:\Office Live\app\office-live-mcp.exe" uninstall
```

Удаление проходит по всем регистрациям из state, включая project/custom, и известным старым пользовательским путям.
Если отпечаток записи изменён пользователем, запись остаётся с сообщением. Если такая запись ещё указывает на наш EXE
или конфигурацию нельзя прочитать, файлы программы сохраняются. Исправьте указанный файл, вручную уберите только `office-live`
или повторите `setup` для принятия новых настроек на учёт, затем повторите `uninstall`.

Собственные файлы определяются по манифесту с SHA-256. Чужие и изменённые файлы сохраняются, границы корня и reparse points
проверяются до удаления. Удаление через symlink/junction запрещено. При запуске удаления из самого EXE файлы снимает скрытый
процесс PowerShell после его выхода; это **назначенное**, а не уже подтверждённое удаление. Окончательный список удалённых
файлов, остатков и ошибок — `%LOCALAPPDATA%\office-live-mcp\uninstall-report.json` (`pending` → `complete`).
Если там ошибки, закройте клиентов и повторите `app\office-live-mcp.exe uninstall --target "D:\Office Live"` из распакованного архива.
Журналы, state, резервные копии и вспомогательный `.ps1` остаются рядом с отчётом для восстановления; удалить их можно вручную
после проверки. Пустой корень программы удаляется, пользовательские остатки перечисляются с полными путями.

### Что именно проверяется

Отчёт различает: **программа установлена**; **EXE запускается** (`tools --json`); **MCP отвечает**
(`initialize` → `notifications/initialized` → `tools/list`, завершение по закрытию stdin); **запись клиента записана и
прочитана обратно**. Это не подтверждение, что запущенный клиент загрузил сервер: **нужен перезапуск клиента** и проверка в нём.
Проверки установки и сборки не вызывают инструменты и не обращаются к открытым Excel/Word. `doctor` — отдельная ручная
диагностика, которая может обращаться к работающему Office.

Диагностика Python/EXE — UTF-8 в stderr. Stdout в режиме serve содержит только UTF-8 JSON-RPC. Проверочный клиент
отдельно дренирует stderr с заменой повреждённых байтов, но любую не-JSON строку/ошибку UTF-8 в stdout считает ошибкой.
Все ожидания запуска, ответа и завершения ограничены таймаутами; по таймауту завершается только созданный проверочный процесс.

Portable-режим **не поддерживается, в планах**. Автономный архив содержит зависимости, но предназначен для установки:
регистрации содержат абсолютный путь. Установка для всех пользователей не поддерживается, профили других пользователей не меняются.
Перемещение установленной папки вручную не поддерживается. Очень длинные пути библиотек PyInstaller (около/свыше 260 символов)
могут не запускаться в Windows: используйте более короткие пути распаковки и установки; `install.cmd` предупреждает.

### Исходники и проверка разработчиком

Сохранены `install.cmd` в клоне, `pip install .`, `python -m office_live setup` и `python server.py`.
Команда `install` предназначена для готового EXE; из исходников `setup` регистрирует текущий Python и абсолютный `server.py`.
Из исходников нужны Python 3.10+ и загрузка зависимостей при подготовке окружения.

```bat
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt pytest ruff pyinstaller
.venv\Scripts\python -m office_live setup --yes --clients codex
.venv\Scripts\python -m office_live config generic
.venv\Scripts\python -m office_live config cursor --write --readonly
.venv\Scripts\python -m ruff check .
.venv\Scripts\python -m pytest tests -q
.venv\Scripts\python packaging\build.py
```

Юнит-тесты переопределяют USERPROFILE, HOME, APPDATA, LOCALAPPDATA и CODEX_HOME до импорта приложения; живые Office-тесты
по умолчанию пропущены. `tests/test_acceptance.py` автоматически использует архив из `dist` (или `OFFICE_LIVE_TEST_EXE`),
а при его отсутствии проверяет разработческий сценарий из исходников. Установку/переключение/откат дополнительно проверяют
тесты с подставным EXE и сбоями файловой системы. Сборка использует короткий `%TEMP%\olb-*` и проверяет настоящий EXE по MCP
в режимах full и readonly на отдельном временном профиле. Python и Office на машине пользователя не устанавливаются сборщиком.

## Как с этим работает агент

Сервер при подключении отдаёт агенту инструкцию. Суть: **список → осмотр → правка → проверка**.

```
excel_list_workbooks / word_list_documents      что открыто, что активно
excel_workbook_info · excel_read_range ·        осмотреться
excel_profile_range · word_get_structure
excel_write_range · excel_format_range ·        изменить (ответ содержит контрольное чтение)
excel_pivot_filter · word_insert_text …
excel_render_range_image · excel_find_issues    проверить глазами/аудитом
```

Примеры запросов пользователя и цепочек:

* **«Отформатируй таблицу, подсвети просроченное»** → `excel_get_selection` (что выделено) → `excel_format_range` (шапка, границы, форматы чисел) → `excel_conditional_format(rule="formula", formula='=AND($C2<TODAY(),$D2="")')` → `excel_render_range_image`.
* **«Сделай сводную по регионам, отфильтруй топ‑3, добавь срез по продукту»** → `excel_create_pivot_table` → `excel_pivot_filter(action="top", …)` → `excel_manage_slicers(action="add", …)`.
* **«Скрой выполненные строки»** → `excel_hide_rows_columns(where={"column": "Статус", "operator": "equals", "value": "Выполнено"})`; в сводной — `excel_pivot_filter(mode="hide")`.
* **«Перенеси таблицу из Word в Excel»** → `word_list_tables` → `bridge_word_table_to_excel`; **обратно** — `bridge_excel_range_to_word_table` (или `…_to_word_picture`, `bridge_excel_chart_to_word`).
* **«Разошли акты по строкам таблицы»** → `bridge_excel_to_word_documents` (шаблон с `{{Колонка}}`, на выходе .docx и по желанию PDF).

### Сделать аналог образца с новыми данными

Образец — любой существующий файл (например, график выпуска документации `.xlsm` с шапкой, цветовыми уровнями и макросами):

1. `office_inspect_file(path=…)` — без открытия: листы, объединения, заморозка, **правила условного форматирования**, макросы (имена процедур и, по запросу, исходный код).
2. `excel_create_from_template(template_path=…, new_path=…)` — точная копия (формат, ширины столбцов, объединения, условное форматирование, формулы, имена, макросы). Образец не меняется.
3. `excel_describe_layout` — **чертёж**: где кончается шапка (заморозка), столбцы (заголовки RU/EN, ширина, скрытые, формат, тип данных, типичные значения, формула столбца — в A1 и R1C1), **виды строк по внешнему виду** (с учётом условного форматирования) и иерархия кодов (`048.01.03` → уровень по числу точек), правила в английской записи с цветами.
4. `excel_clear_range(what="contents")` на области данных → `excel_write_range` с новыми данными (`value_mode="text"` для кодов) → `excel_set_formula(formula=<formula_r1c1>, r1c1=true)` или `excel_autofill` для формул → при необходимости `excel_copy_range(dest_cell="A200:AT300")`, чтобы растиражировать оформление строки.
5. `excel_render_range_image` — убедиться, что цвета уровней и просрочки на месте; `excel_save`.

Готовый «чертёж» в JSON без участия агента: `python examples\analyze_sample.py "путь\к\образцу.xlsm"`.

### Сравнение диапазонов Excel

`excel_compare_ranges(cells_a="A1:D100", workbook_a="Смета.xlsx", sheet_a="Было", sheet_b="Стало")`
сравнивает диапазоны без изменения книг. Пустые параметры B наследуют A; можно указать другую книгу, в том числе
в другом экземпляре Excel. Цели должны различаться. Целые строки/столбцы обрезаются по UsedRange; несколько областей
одним вызовом не принимаются.

`compare="values"` сравнивает Value2, используя типизированный Value для ISO-дат, как `excel_read_range`:
это сохраняет и даты, и точность обычных чисел. Пусто равно `""`, но не нулю; число и текст, bool и число различаются.
Ошибки сравниваются по тексту. `compare="formulas"` сравнивает английский Formula, константы — как значения;
одинаковые относительные формулы в разных адресах не пересчитываются относительно начала блока.
Лимит обоих режимов — 200 000 ячеек на сторону. `compare="formats"` сравнивает только NumberFormat,
жирность, курсив, цвет шрифта и заливки, без условного форматирования; лимит — 5 000 ячеек на сторону.
Оба размера проверяются до чтения данных.

`match="position"` сравнивает пересечение размеров, а лишние полосы возвращает адресами в `only_in_a/b`.
`match="key", key_column="Код"` сопоставляет строки по ключам, столбцы по заголовкам первой строки.
Вместо заголовка допустима буква абсолютного столбца, разрешаемая отдельно в каждой стороне.
Пустые ключи пропускаются и считаются; дубли ключей или заголовков вызывают отказ. Типы ключей различаются;
числовой допуск к ключам не применяется. `ignore_case` и `ignore_whitespace` действуют также на ключи и заголовки:
второй параметр обрезает и схлопывает пробельные символы, включая NBSP. `tolerance` — конечный неотрицательный
абсолютный допуск. `summary` содержит число сравнённых ячеек/строк и отличий по типам; `differences` — первые
`max_differences` (1–2000, по умолчанию 200), `truncated` и `remaining_differences` описывают остаток.
Тексты длиннее 200 символов сокращаются с пометкой; отсутствующие заголовки — в `headers_only_in_a/b`.

### Очистка текстов Excel

`excel_clean_text(workbook="Данные.xlsx", sheet="Лист1", cells="A:C", operations=["clean", "trim", "text_to_number"])`
по умолчанию делает **только предпросмотр**: счётчики и до 50 примеров, без снимка, журнала изменений или листа «Лог».
Сам инструмент относится к пишущим и в readonly не регистрируется. Для записи повторите вызов с `preview=false`.
Обязательный прямоугольник ограничен 100 000 ячеек после обрезки целых строк/столбцов.

Порядок фиксирован: `clean` → `trim` → один из `upper/lower/proper` → `text_to_number`.
`clean` удаляет управляющие символы, кроме LF, и U+200B–U+200D/U+FEFF; `trim` обрезает и схлопывает обычные пробелы,
U+00A0/U+202F заменяет пробелом, сохраняет переводы строк. `proper` использует Python `str.title`.
Числа распознаются через `smart_number`: коды с ведущими нулями, даты, номера разделов, телефоны с разделителями
и длинные номера с плюсом, записи более 15 цифр сохраняются текстом. Без явного `decimal_separator` одиночная точка
или запятая с тремя цифрами справа неоднозначна: число не преобразуется, адрес попадает в `ambiguous`.
Остальные запрошенные операции при этом применяются. Явные `","`/`"."` снимают эту неоднозначность.
Ограничение smart_number на 15 цифр консервативно: считается вся запись, включая нули перед дробной частью.

Защищённый лист и пересечение со сводными отклоняются до снимка/записи; формулы, не-тексты и неглавные ячейки
объединений пропускаются со счётчиками. Пишутся только изменившиеся ячейки вертикальными группами; объединённая
главная ячейка пишется отдельно. Опасный для автоматического распознавания текст и исходный апостроф защищаются
апострофом, затем проверяются тип и значение. Исправленные после контрольного чтения ячейки перечислены
в `rewritten_as_text`; у преобразованных чисел формат `@` меняется на General и попадает в `format_changed`.

Запись начинается только после успешного снимка всего обработанного диапазона. Если снимок недоступен, превышен `OFFICE_LIVE_UNDO_MAX_CELLS` или выбрана служебная область журнала, правок не будет.
При `OFFICE_LIVE_UNDO=0` (отмена выключена владельцем) очистка и сортировка работают без снимка, как остальные инструменты.
`office_undo` восстанавливает содержимое и изменённые числовые форматы; поздняя правка содержимого, числового формата
или апострофа в том же диапазоне блокирует отмену. При сбое COM история сохраняется: ошибка сообщает `applied`,
`remaining`, `unverified` и изменённые форматы. `applied` — число подтверждённых чтением результатов;
нечитаемые ячейки не объявляются успешно записанными.
Если Office не даёт прочитать отпечаток частичного результата, снимок сохраняется, но отмена требует `force=true`:
отличить последующую ручную правку от оборвавшейся записи уже нельзя. Ответ и история прямо указывают эту причину.

### Сравнение документов Word

`word_compare_documents(original="Договор.docx", revised="D:\\Документы\\Договор-новый.docx")`
создаёт новый несохранённый документ с исправлениями. Оба источника выбираются через обычную проверку доступа,
строгого имени и AutoSave и должны принадлежать одному экземпляру Word. Файлы на диске проверяются до открытия;
неоткрытые источники временно открываются в том же экземпляре без окна, только для чтения, без недавних файлов,
с отключёнными макросами и паролями-пустышками против диалогов. Временные документы закрываются без сохранения
даже при ошибке; уже открытые остаются открытыми. Отдельный экземпляр Word инструмент не запускает.

`granularity="word"` или `"character"`; флаги `compare_formatting/case/whitespace/tables/headers/footnotes/comments/moves`
по умолчанию true. Все 16 аргументов CompareDocuments передаются позиционно: также true для CompareTextboxes,
CompareFields и обязательного IgnoreAllComparisonWarnings. Если в источниках были исправления, `warnings` сообщает,
что Word считает их принятыми при сравнении; сами источники не принимаются и не сохраняются.
Ответ содержит имя результата, число исправлений по типам, первые 30 исправлений с автором и текстом до 200 символов.
Для неизвестных/составных типов есть счётчик `other` и исходный `type_code`. **Отмена — закрыть результат без сохранения**;
шаг `office_undo` для сравнения не создаётся.

### Сортировка таблиц Word

`word_sort_table(document="Отчёт.docx", table_index=1, keys=[{"column": 2, "type": "number", "order": "desc"}])`
сортирует строки по 1–3 неповторяющимся столбцам (номера с 1). `type`: text/number/date; `order`: asc/desc;
`header=true` сохраняет первую строку, `case_sensitive=false` игнорирует регистр. В ответе первые 20 строк,
размер таблицы и `sorted_rows` без заголовка.

До изменения проверяются наличие таблицы и строк данных, Uniform и число ячеек, отсутствие вложенных таблиц,
все ключи, отключённый Track Changes и отсутствие защиты документа. Числа/даты каждой строки проверяются средствами
Windows с языком таблицы; при смешанном/неопределённом языке используется язык Windows. Тот же LCID явно передаётся
в 17-й аргумент Table.Sort и возвращается как `language_id`. Для дат обязателен четырёхзначный год: неполные даты
не угадываются. Неразбираемые ячейки перечисляются в ошибке до сортировки.

После проверок требуется доступный Word UndoRecord. При занятой пользовательской записи или неудаче подготовки
инструмент откажет без сортировки. `office_undo` возвращает исходный порядок; поздняя ручная
правка блокирует его без `force`. При ошибке COM сохраняется запись отмены и сообщается число изменившихся позиций
строк; если Word перестал отвечать на чтение, это число явно помечается `unknown`.
При недоступном отпечатке результата завершённая запись UndoRecord сохраняется с требованием `force=true`.
Если Word не подтвердил завершение самой записи UndoRecord, ответ честно сообщает, что отмена недоступна.

## Журнал и отмена

Пишущие вызовы, сохранение, открытие и экспорт в файл оставляют строку в отдельном Markdown-журнале каждого
фактически выбранного документа: `%LOCALAPPDATA%\office-live-mcp\journal`. Ошибки также записываются, длинные текстовые
аргументы по умолчанию скрыты. Прочитать последние строки: `office_journal(workbook="Книга.xlsx", action="read", lines=50)`
или передать `document` для Word; `action="status"` показывает путь и состояние журнала.
Имя файла: `<имя документа> [<первые 12 hex-символов SHA-1 пути или имени в нижнем регистре>].md`.
Старые журналы с 8 символами остаются на диске; новые записи и чтение используют имя с 12 символами.

Перед первой правкой книги агент один раз предлагает вести лист **«Лог»**. `office_journal(workbook="Книга.xlsx",
action="enable_sheet")` включает его; настройка хранится в скрытом имени книги `OfficeLive_Log` и сохраняется вместе с ней.
`disable_sheet` отключает записи, сохраняя лист; `delete_sheet=true` также удаляет его. Word ведёт только журнал на диске.

`office_undo(file="Книга.xlsx", action="history")` показывает стек, `office_undo(file="Книга.xlsx", steps=1)` отменяет
последнюю правку. Для Word передайте имя документа. По умолчанию хранятся 50 шагов и не более 200000 ячеек на снимок Excel.
Excel использует скрытую служебную книгу, Word — собственные записи UndoRecord. История Excel **Ctrl+Z всё равно очищается**
COM-правками. Снимки и стек доступны только в текущем сеансе сервера; закрытие служебной книги делает её снимки недоступными.

Неподдерживаемые изменения (например, сводные таблицы и фильтры) и превышение лимита создают **барьер**: отмена останавливается
на нём, не перескакивая к более старым правкам. Открытие, создание, сохранение, экспорт и закрытие файлов не добавляют шагов.
Расхождение отпечатка формул/значений, агрегированного оформления проверяемой области или структуры листов после агента
блокирует отмену. Оформление Excel проверяется целиком по диапазону: числовой формат, имя/размер/жирность/курсив/подчёркивание/
цвет шрифта, цвет/узор заливки, выравнивание, перенос текста и объединение. **Правка оформления одной ячейки внутри уже
смешанного диапазона может остаться незамеченной**, если агрегированное значение по-прежнему смешанное (`None`).
Word дополнительно проверяет текст существующих колонтитулов всех разделов, число и тексты комментариев, число сносок,
концевых сносок и фигур; пометки фоновой проверки орфографии и идентификаторы сеансов правки игнорируются.
Отмена создания или копирования листа требует `force=true`, если при завершении операции на нём были фигуры (включая
диаграммы, надписи, изображения и срезы), таблицы, сводные таблицы, условное форматирование, проверка данных, заметки или
обсуждения: их ручные правки нельзя надёжно выявить по отпечатку; причина показана в `history`.

`force=true` разрешает потерю поздних правок. В Word он **также отменяет поздние ручные действия пользователя**, пока не
достигнуто состояние перед шагом агента, максимум за 20 нативных отмен на один шаг агента. Ответ содержит `native_steps`
(суммарно и для каждого отменённого шага). Если исходное состояние не достигнуто, шаг остаётся барьером, а сообщение указывает,
сколько нативных действий уже отменено, включая ручные правки; частичная отмена не откатывается обратно.

Удалённые листы, строки и столбцы восстанавливаются, но формулы вне снимка, которые ссылались на удалённое, остаются `#REF!`.
Отмена `excel_copy_range(move=true)` копирует назад снимки источника и назначения: формулы вне этих снимков, перенаправленные
перемещением, продолжают ссылаться на назначение. Эти ограничения возвращаются предупреждением вместе с результатом.
Действия `history`, `read` и `status` доступны и в режиме только чтения.

## Безопасность

Сервер даёт агенту реальный доступ к вашим документам и работает с **правами пользователя** — это не песочница. Что именно он гарантирует
и чего не гарантирует:

**Гарантирует (проверено автотестами):**

* Ничего не сохраняется само; `*_save_as` и экспорт (PDF, PNG диаграммы) не перезаписывают файл без `overwrite=true`; расширения ограничены, запись
  в системные папки и автозагрузку (`XLSTART`, `Startup`, `Windows`, `Program Files`) запрещена — и при сохранении уже открытого файла, а не только «Сохранить как».
* **AutoSave.** Книги и документы с включённым автосохранением (OneDrive/SharePoint) записываются в облако после каждой правки, до того как пользователь
  успеет что-то проверить, поэтому пишущие инструменты на них **отказывают** (читать, сохранять, закрывать можно). Выключите AutoSave у файла или
  задайте `OFFICE_LIVE_AUTOSAVE=allow`.
* Закрытие книги/документа с несохранёнными изменениями — только с явным `save=true` или `discard=true`; удаление листа — только с `confirm=true`;
  сами приложения сервер не закрывает. Перевод формул на язык интерфейса идёт во временной скрытой книге, а не во временном листе вашей книги. Снимок диапазона
  (`excel_render_range_image`) на долю секунды ставит на лист временную диаграмму и тут же удаляет её. Это **изменение книги**, поэтому инструмент объявлен не
  «только читающим» (`readOnlyHint=false`), хотя в режиме `readonly` доступен: содержимое остаётся прежним, но Excel помечает книгу как изменённую (флаг
  «сохранено» сервер намеренно не подменяет — иначе мог бы скрыть настоящую правку, сделанную в те же миллисекунды), а история отмены (Ctrl+Z) очищается.
  AutoSave на время снимка приостанавливается, а если приостановить нельзя — снимок отклоняется; события Excel на это время отключены.
* **Макросы.** Файлы открываются с отключёнными макросами (`AutomationSecurity = ForceDisable`); если отключить не удалось — файл **не открывается**.
  На время пишущих вызовов (и снимка диапазона) Excel не вызывает события (`Worksheet_Change`, `BeforeSave`, `SheetActivate` …) уже открытых книг;
  если отключить их не удалось, вызов **отклоняется** — `OFFICE_LIVE_ENABLE_EVENTS=1` разрешает события осознанно.
  Сервер не запускает макросы, но не может остановить макросы, надстройки и события, которые пользователь уже включил в своей сессии.
  Открытие использует подставной пароль (чтобы зашифрованный файл вызвал ошибку, а не диалог; на реальном зашифрованном файле не проверялось).
* Цель правки названа точно: при `OFFICE_LIVE_STRICT_TARGET=1` пишущие инструменты принимают только точное имя/путь книги или документа и явное имя листа;
  без него допустима уникальная подстрока и «активная». Если лист указан дважды по-разному (`sheet` и `Лист!A1`), это ошибка.
* Закрытие и удаление не происходят «заодно»: деструктивные действия многоактных инструментов помечены `destructiveHint`, а ответы пишущих
  инструментов говорят, что реально изменилось (число изменённых ячеек, созданные файлы, оставшиеся после сбоя объекты).
* Текст внутри ячеек и документов считается недоверенными данными (инструкция агенту это говорит прямо).

**Не гарантирует:**

* `readonly` защищает документы **от изменения**, а не от чтения: агент по-прежнему видит содержимое всего открытого, и оно попадает в контекст модели.
  Для конфиденциального используйте `OFFICE_LIVE_ALLOWED_DIRS` (и/или закройте лишние файлы). `office_inspect_file(include_vba_source=true)` показывает и код макросов.
* `OFFICE_LIVE_ALLOWED_DIRS` ограничивает **файлы**: открытие/сохранение/вставку по пути и видимость уже открытых документов (файл вне зоны не виден в списках
  и недоступен по имени). Симлинки и junction разрешаются до реального пути. Несохранённый документ без пути считается разрешённым; содержимое,
  которое агент скопировал в разрешённый документ, зона не контролирует.
* `OFFICE_LIVE_ALLOW_EVAL=1` (`office_run_python`) обходит все ограничения выше — это консоль с правами пользователя; включайте осознанно.

Настройки — переменные окружения (задаются в конфигурации клиента, см. `config --readonly` и др.). Неверное значение ограничивающей настройки
(`OFFICE_LIVE_TOOLSETS` без единой известной группы, `OFFICE_LIVE_AUTOSAVE` не из `block|allow`) **останавливает запуск** с понятным сообщением, а не включает все инструменты:

| Переменная | Значение |
|---|---|
| `OFFICE_LIVE_MODE` | `full` (по умолчанию) или `readonly` — пишущие инструменты **не регистрируются вовсе** (многоактные — только их действия чтения), файлы открываются только на чтение; создание новой книги/документа тоже запрещено |
| `OFFICE_LIVE_TOOLSETS` | `all`, `core`, `excel`, `word` или список групп через запятую |
| `OFFICE_LIVE_ALLOWED_DIRS` | каталоги через `;` — открывать/сохранять/вставлять файлы только оттуда; остальные открытые файлы не видны |
| `OFFICE_LIVE_STRICT_TARGET` | `1` — пишущие инструменты требуют точное имя книги/документа и имя листа (без «активного» и без подстрок) |
| `OFFICE_LIVE_AUTOSAVE` | `block` (по умолчанию) — не писать в файлы с включённым AutoSave; `allow` — разрешить |
| `OFFICE_LIVE_ENABLE_EVENTS` | `1` — не отключать события Excel на время пишущих вызовов |
| `OFFICE_LIVE_AUDIT_LOG` | путь к jsonl-журналу пишущих вызовов: запись `start` до выполнения и `end` после (результат, длительность, реально выбранные книги/документы); длинные текстовые аргументы скрыты |
| `OFFICE_LIVE_AUDIT_CONTENT` | `1` — писать в журнал фрагменты текстовых аргументов (по умолчанию скрыты: в них может быть содержимое документов) |
| `OFFICE_LIVE_JOURNAL` | `on` (по умолчанию) / `off` — Markdown-журналы документов |
| `OFFICE_LIVE_JOURNAL_DIR` | каталог журналов; по умолчанию `%LOCALAPPDATA%\office-live-mcp\journal` |
| `OFFICE_LIVE_UNDO` | `on` (по умолчанию) / `off` — запись отмены |
| `OFFICE_LIVE_UNDO_DEPTH` | положительное целое, по умолчанию `50`; старые снимки удаляются вместе с записями |
| `OFFICE_LIVE_UNDO_MAX_CELLS` | положительное целое, по умолчанию `200000`; большие изменения создают барьер |
| `OFFICE_LIVE_ALLOW_EVAL` | `1` — включить `office_run_python` (эквивалент выдачи агенту консоли) |
| `OFFICE_LIVE_BUSY_TIMEOUT` | сколько секунд ждать, пока Office «занят» (редактирование ячейки, диалог); по умолчанию 20 |

Если пользователь редактирует ячейку или открыт диалог, COM-вызовы отклоняются: сервер сам повторяет их, а по истечении
таймаута просит агента попросить пользователя выйти из режима редактирования.

## Особенности COM (важно при доработке)

Найдены живыми пробами на этой машине; закреплены в коде и тестах:

* **Только позиционные аргументы.** В late-binding pywin32 именованные аргументы молча превращаются в позиционные по порядку
  (`Worksheets.Add(After=x)` вставляет лист *перед* x). Прокси `office_live.com.Proxy` запрещает `kwargs`.
  Пропущенные необязательные Variant-аргументы — `None`; `pythoncom.Missing` в первой позиции «роняет» остальные аргументы,
  а для типизированных параметров нужно явное значение по умолчанию.
* **`Range.Resize()` и `Offset()`** в late-binding возвращают не тот диапазон — адреса считаются по `parse_a1`/`a1_range`.
* **Региональные настройки.** Через COM `NumberFormat` принимает формат в *локальной* записи (в русском: `0,00`; `0.00` отвергается),
  а формулы условного форматирования и проверки данных — на *локальном* языке функций. Сервер сам переводит: агент пишет и читает
  `#,##0.00` и английские формулы. `Range.Formula` при этом всегда английская.
* **Excel `Value=` разбирает строки как ввод** (`"123"` → число, `"=A1"` → формула, `"2026-10-04"` → дата) — для кодов есть `value_mode="text"`.
* **Word `Find.Execute(Replace=all)`** подстраивает регистр замены под найденное и трактует `\1` как группу — буквальная замена делается через `Range.Text`.
  Для несохранённого документа `ExportAsFixedFormat` обнуляет имя документа — поэтому сначала `word_save_as`.
* **Соседние таблицы Word сливаются**, а «пустой абзац перед таблицей» нельзя вставить в начало ячейки — см. `ensure_free_anchor`.
* **COM-объекты нельзя освобождать после `CoUninitialize`**: `run_com` освобождает прокси и `gc.collect()` до выхода из апартамента.
* Снимок диапазона (`CopyPicture`) рисует только видимое: свёрнутое или маленькое окно книги даёт пустую картинку — сервер временно разворачивает окно, ждёт перерисовки, делает снимок через временную диаграмму на самом листе и возвращает прежнее состояние окон (но не флаг «сохранено»). Проверено на стенде: вставка в диаграмму ДРУГОЙ книги даёт пустую картинку, а внешнее чтение буфера обмена (`ImageGrab`) роняло Excel (исключение `0xC015000F`) — оба способа отвергнуты. Если снимок пуст при непустых данных — честная ошибка с причиной.
* **pywin32 прячет «приложение занято» за `AttributeError`** (сбой `GetIDsOfNames`): `Proxy` выясняет настоящую причину и повторяет вызов, а не принимает занятость за отсутствие свойства.
* Перевод формул на язык интерфейса (для условного форматирования и проверки данных) идёт через временную скрытую книгу; ссылки на другие книги в таких формулах не поддерживаются (Excel открыл бы диалог выбора файла).
* `Table.Split()` в Word здесь отвечает «Неверный параметр» — абзац над таблицей создаётся разрезом предыдущего абзаца (или `Selection.SplitTable` для таблицы в начале документа).
* Автоматизация очищает историю отмены (Ctrl+Z) пользователя.

## Ограничения

* Только Windows и десктопные Excel/Word. Режим защищённого просмотра и файлы с паролем не поддерживаются; экземпляры другого сеанса/уровня прав не видны.
* Файлы с включённым AutoSave (OneDrive/SharePoint) — только чтение, пока AutoSave не выключен.
* Макросы не запускаются (читаются только их исходники); создавать VBA-код нельзя. Для остального есть `office_run_python` (по явному включению).
* Диаграммы-«chartex» (воронка, водопад, гистограмма нового типа) и сводные по модели данных не поддерживаются.
* `Comment.Done` (пометить комментарий решённым) в ряде сборок Word недоступен через автоматизацию — инструмент сообщает об этом.
* Exe собран PyInstaller: если полный путь к его библиотекам длиннее 260 символов (архив распакован очень глубоко,
  длинный `--target` или глубокий профиль пользователя), Windows не загружает DLL и программа не запускается
  («Имя файла или его расширение имеет слишком большую длину»). Распаковывайте архив неглубоко, например в «Загрузки».
  В готовом архиве `install.cmd` (исходник: `packaging/install.cmd`) предупреждает до запуска exe, если путь
  `%~dp0app\_internal` длиннее 200 символов. Установка продолжается; длину будущего `--target` эта проверка не оценивает.
* План «этап A» (надстройка Office.js + HTTPS-мост, чтобы работать без COM) пока не реализован; COM-бэкенд остаётся основным.

## Тесты

```bat
.venv\Scripts\pip install -e .[dev]
.venv\Scripts\python -m pytest tests                                   :: юнит-тесты, Office не нужен
set OFFICE_LIVE_LIVE_TESTS=1 && .venv\Scripts\python -m pytest tests\live   :: живые тесты с реальными Excel и Word
```

Для каждого исправленного дефекта есть регрессионный тест: юнит на подделках COM (`tests/test_audit_infra.py` и др.) и живой
(`tests/live/test_live_audit.py`). Живые тесты создают собственные черновые книги/документы во временной папке и закрывают **только их**;
Word закрывается, лишь если его запустили сами тесты (до прогона он не работал) и в нём не осталось документов; Excel не закрывается.
Ваши открытые файлы не затрагиваются, но прогон занимает буфер обмена и временно сворачивает/разворачивает окна своих книг —
не работайте в Excel во время живого прогона.
